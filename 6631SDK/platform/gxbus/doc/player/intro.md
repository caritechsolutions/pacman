
# 音视频系统

## 基本概念

音视频系统是什么？为什么需要音视频系统？它到底能够做什么？带着这几个问题，我们先看多媒体应用开发所面临的挑战：

+ 多媒体数据量巨大，应如何保证数据处理的高效性；
+ 如何让音频和视频时刻保持同步；
+ 如何用简单的方法处理复杂的媒体源的问题，包括本地文件、计算机网络、广播电视以及其他一些数码产品等；
+ 如何处理各种各样的媒体格式问题，包括 AVI、ASF、MPEG、REAL、MP4 等；
+ 如何处理各种各样的音视频编码方法，包括 H264、Real、XVID/DIVX、OGG 等；
+ 如何用简单的方法支持目标系统中不可预知的硬件等；

音视频系统设计初衷就是尽量让应用开发人员从复杂的数据传输、硬件差别、同步性、编解码方式、打包方式等工作中解脱出来，这些工作由播放系统来完成。应用开发者只需通过这个集合的简单的接口调用，不需要关心音视频播放的复杂流程，就能够实现音频 、 视频 、 图片 、 字幕 等多种媒体的播放，并对播放过程和音视频输出进行控制。这样，基于播放系统进行多媒体应用程序开发就变的非常的简单了！

音视频系统包含 GxPlayer 和 MediaAPI 两个模块。

## GxPlayer 模块

GxPlayer 模块是对播放器功能的封装，直接提供播放器级别的播放、录制、控制等接口。
+ 优点：简单、易用、功能强大、接口丰富。
+ 缺点: 封装层次较高，不够灵活。

更多信息请参考： [Player 用户手册](./gxplayer/intro.md)

## MediaAPI 模块

MediaAPI 模块是音视频组件的封装，直接提供数据源、音视频解码、音视频输出等接口；播放功能需要用这些 API 去组装实现。
+ 优点：封装层次较低，相对灵活。
+ 缺点: 使用不方便、功能单一；目前只支持 DVB 播放 和 TS 注入播放。

更多信息请参考： [MeidaAPI 用户手册](./mediaapi/intro.md)

## 如何选择

+ 建议优先选择 GxPlayer 模块。
+ 如果 GxPlayer 模块 无法满足需求，可以向我们提需求或者尝试使用 MediaAPI 模块。
